# 04｜頁面與 UX 模式

> 依功能整理每個空間的版面與互動規則。UX 模式依據源自 [UX 稽核](../ux-audit-and-benchmark.md) 與歷史設計分析（[已棄置 v1 參考分析](./research/reference-analysis.md)）；視覺系統已全面更新為 v2.5。
> 標 `U-xx` 的是改進待辦。
> **已完成**（2026-11-28）：U-01～U-16 全部完成。U-07 報名時的公開／匿名切換原本就有；U-14 簡化為「每筆可從公開足跡隱藏」，整頁可見度沿用既有的公開／同校／私人設定；U-16 稽核後沒有表單會在出錯時清空輸入。

## 全站通則

- **有盡頭的瀏覽**：列表看完時明確提示「看完了」，並提供其他主題入口；不做無限捲動。（提案書 §三.2）
- **不顯示人氣數字**：按讚、追蹤、人數、排名、契合度都不出現在介面上。非競爭性的集體累計可以。（PRD §1.2）
- **質性信任訊號**：近 30 天活躍、零基礎可、非社員可、問答有回覆。
- **圖片不裁切**：顯示比例＝原圖比例。（PRD、W3C masonry）
- **先給價值再要承諾**：先看、先試，最後才請登入；導向登入時一定帶 `callbackUrl`／`returnTo`，登入後回到原處。
- **錯誤不清空輸入**；錯誤訊息放在出錯的地方。（NN/g）
- **可復原的操作用「復原」，不可逆的才確認。**（NN/g）

## 1. 別的聚：探索首頁

| 區塊 | 規則 |
| :--- | :--- |
| 首屏依狀態切換 | 第一屏只放一個主角（參考 Meetup、Pinterest 登入前後分版，Netflix 模組依人排序）。**第一次來、沒有目標**：主角是測驗卡（標題＋「開始挑選」＋「先隨便看看」＋搜尋膠囊），旁邊是本週活動貼紙卡。**做過測驗、回訪或已登入**：不放宣傳標語，只留一列搜尋膠囊，作品流從第一屏開始，本週活動移到這批作品之後。**幹部待辦或追蹤社團有活動**：提示條放最上面。「先隨便看看」會被記住，之後不再出現測驗卡 |
| 頁首 | 圓黑（`font-display`）標題只出現在首次造訪的測驗卡；其他狀態保留 `sr-only` 的 `h1` 給螢幕閱讀器 |
| 分頁 | 「社團動態」（作品與日常）／「近期活動」；平行、1–2 個詞 |
| 搜尋 | 自然語言；提示用關鍵詞組合（「週末、零基礎、不用買器材」）；建議詞不能導向零結果（NN/g） |
| 篩選 | 六大領域與細分興趣貼紙，可多選（符合任一個就列出）；測驗選的興趣直接套用成條件；已套用條件列在結果上方，可單獨移除＋「撕掉全部」（Baymard，`U-06`） |
| 社團動態 | 保留原比例的瀑布流（手機 1 欄、平板 2 欄、桌機 3 欄）；卡片＝圖＋標題＋社團一行＋最多 2 個標籤 |
| 近期活動 | 依日期排序的雙打洞票根卡；不做倒數與急迫感 |
| 結尾 | 「這批看完了」＋其他領域入口（空狀態：「這裡還空著」） |

## 2. 我的聚：社團主頁（對外門面）

依序：
1. **頁首**：扇貝貼紙標誌、圓體展示字社團名、學校、認證徽章、一句介紹、主要行動「追蹤」。
2. **信任標籤列**：近 30 天活躍、零基礎可、非社員可、問答回覆——所有社團都顯示，不只認證社團（`U-02`）。
3. **追蹤二選一**：「全部動態」／「只看活動」，並提供行事曆訂閱（Luma，`U-04`、`U-10`）。
4. **置頂 FAQ** 2–3 則：放在作品牆之前，或頁首提供錨點（`U-03`）。
5. **近期活動**：票根卡。
6. **代表作品**：釘選 3–4 件（Letterboxd，`U-05`），其後是作品與日常的瀑布流，不裁切（`U-01`）。
7. **集體累計**（例：「本學期社員共同累積 N 則日常」）：可以顯示，但不和其他社團比較。
8. **外部連結**：IG、Discord 等；過濾掉無效或示範用連結。
- 未認領的社團：顯示「待認領」，不顯示活躍狀態，並提供認領入口。

## 3. 活動頁與報名

| 區塊 | 規則 |
| :--- | :--- |
| 頁首 | 封面（不裁切）、圓體展示字活動名、主辦社團（扇貝貼紙）、領域標籤 |
| 關鍵資訊 | 時間（或「時間待定」「喬時間」標籤）、地點、費用、零基礎可、非社員可、學習時數 |
| 時間投票 | 每個時段可答「可以／不行／也許」；主辦鎖定後**投票自動轉成報名**，並通知投票者（Partiful） |
| 報名 | 標題「報上名來！」；有名額上限時寫「剩下 N 個位置」（活動自己的名額，不是人氣數字）；名單只選「公開／匿名」，名字一律用個人頁的名稱，不在這裡改（`U-07`） |
| 參加者 | 只顯示幾個頭像，不顯示人數；主辦可整份隱藏（Luma，`U-07`） |
| 確認狀態 | 卡位後出現黃色「入場券」（活動名稱、時間、地點＋「已卡位」蓋章動畫），正下方只有一顆主要按鈕「當日推播我」＝加到 Google 日曆；不再列 Outlook／.ics／訂閱連結（`U-07`） |
| 分享 | 一鍵複製到 IG／LINE／Discord；OG 圖用票根樣式；主辦可隱藏敏感欄位（例：教室號碼）（`U-09`） |
| 活動結束後 | 報名區改為「上傳照片」（限參加者），共享相簿精選回流社團頁（`U-08`） |
| 內文 | Markdown 正確渲染，不外露原始符號 |

## 4. 主辦端：建立活動與宣傳

- 4 段表單（基本資訊、時間地點、參加條件、內容與報名）；已有活動時預設收合，摘要列說明段落。
- 只要求發布所需的最少資訊，進階設定可略過（Luma）。
- **AI 只產生草稿**：從海報讀出的欄位標示「AI 填入，請確認」；日期與地點確認前不能發布（Apple、`U-11`）。
- AI 解析失敗或判斷為活動海報、社課行事曆時，引導到「建立活動」，不讓活動宣傳落進日常動態牆。
- AI 擬的描述旁提示「加一句你自己的話」（Meetup）。
- 宣傳包：IG／LINE／Discord 文案各自可編輯，以社團自己的海報為主，不用 AI 生成圖（Eventbrite 反例，`U-12`）。

## 5. Onboarding 與 Blend

- 不用登入；一頁一題、大按鈕、細進度條；每一步都有「先隨便看看」（Duolingo、NN/g）。
- **只問兩題**：學校（點一下就進下一步；已知學校就跳過）→ 興趣（12 個附 icon 的貼紙一個畫面看完，**沒有預設值、不限數量**）。不問目標與氛圍：測驗的目的是篩掉雜訊，題目越少越好；選項不用作品圖，手機一屏塞不下。
- **越喜歡點越多下**：每點一下浮出「+N」，貼紙角落顯示份數；長按（鍵盤用 Backspace）減一份，不另外放減號按鈕。
- **結果是自己調出來的食物卡**（`RecipeCard`）：特調（分層）或披薩（切片），每個興趣一種配料，份量照點擊次數。只寫「N 份」，不寫百分比。配色由使用者從 5 組色票挑（`PALETTES`，依份量排序上色，相鄰不撞色）；卡片標題印使用者名字（登入用個人頁名稱，可改）。結果頁第一屏只放卡片＋「分享我的特調」＋「存成圖片」，推薦社團放在卡片下方。不幫使用者取類型名稱。
- **分享連結** `/mix?r=…&f=…`：OG 圖就是那張食物卡，打開後顯示朋友的配方，下方是黃底大按鈕「我也來調一份」，直接導向測驗。
- 結果只列和所選興趣有關的社團與活動；沒有就說「這間學校還沒有這類社團的動態」，不拿無關社團湊數。
- 結果出來後才以可跳過的方式請註冊，跳過時結果保留。
- 切換步驟時捲回頂部。
- **Blend 卡**：9:16 分享圖＋1.91:1 連結預覽；內容是「你們共同的 3 個興趣＋1 個推薦社團」，**不顯示契合度分數**（Spotify 反例，`U-13`）；附回到探索的按鈕。

## 6. 個人足跡（`/me`、`/u/[handle]`）

- 「社團日記」時間軸：日期＋活動或作品＋短記（Letterboxd）。
- 學期足跡格：安靜的熱度格，不做連續天數與徽章（GitHub）。
- 每筆足跡可設「公開／社員／僅自己」，並可批次修改；隱藏的項目只對他人隱藏（Strava、GitHub，`U-14`）。
- 收藏（作品）與追蹤（社團、只看活動）分開管理。
- 空狀態一律有導回探索的行動。

## 7. 通知

- 依社團／活動分組（`U-15`）。
- 全部看完時：「都看完了」＋推薦一個近期活動。
- 空狀態：說明哪些事會出現在這裡＋「看看近期活動」。

## 8. 一起聚：跨校交流

| 模式 | 規則 |
| :--- | :--- |
| 跨校共作企劃 | 主題、截止日、作品牆；由參與社團或評審決定，不做公開票選（itch.io） |
| 接力回應 | 一定顯示來源作品與來源社團，可看到整條接力鏈（Dribbble Rebound） |
| 共享資源 | 「複製這份範本」：複製後預設私人，發布時必須標註來源社團（Figma、Hugging Face） |
| 前輩請益 | 校友卡：背景、可回覆的主題；不顯示評分 |
| 排序 | 不用按讚數排序；以時間與主題組織（Product Hunt 停辦票選獎） |
| 用詞 | 全中文白話：「接力回應」「跨校共作企劃」「前輩請益」，不用內部英文代號 |

## 9. 工作區與治理後台

- 工作區（社團管理、我的社團）：色彩與字體一致，形狀與動態收斂；資訊密度優先。
- 治理後台：只換色彩 token；高密度表格；所有不可逆或影響他人的操作（核准、駁回、停權、解除停權、下架、復原）都要確認。
- 介面上不出現原始英文代碼（`owner`、`scheduled`、`open`），一律對應成中文標籤。
