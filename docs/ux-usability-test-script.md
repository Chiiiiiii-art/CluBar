# CluBar 可用性測試腳本（5-User Usability Pilot）

> **驗證範圍說明**：本專案目前尚未上線公開招募真實用戶，因此沒有實測受測數據。以下為依據 ISO 9241-210、NN/g 5-User Test 與 SUS / SEQ 指標設計的標準化測試腳本，供上線或競賽評審前現場測試使用；**未執行前不宣稱任何實測分數或量化結論**。

---

## 1. 測試目標與環境設定

- **方法**：放聲思考（Think Aloud）＋ 任務計時 ＋ 單題難易度量表（SEQ 1–7）＋ 會後系統可用性量表（SUS 10 題）。
- **單人時長**：15 分鐘（3 分鐘破冰＋10 分鐘任務實測＋2 分鐘詞彙理解與 SUS）。
- **測試裝置比例**：
  - 3 位使用 **Mobile Web（`390×844` 直立手機視窗）**
  - 2 位使用 **Desktop Web（`1440×900` 桌機視窗）**
- **受測者招募（5 位對應主要／次要角色）**：
  - `P1`（探索型新生）：從 `/onboarding` 或 `/` 進入，手機為主。
  - `P2`（任務型學生）：以累積藝文／服務學習時數為優先篩選條件。
  - `P3`（社團幹部）：負責宣傳活動與整理社團評鑑／換屆交接。
  - `P4`（一般認證社員）：收到幹部邀請碼後發文記錄社團日常。
  - `P5`（跨校同好／學長姐請益）：想跨校看作品並請教歷屆幹部。

### 主持人開場白（逐字稿，嚴禁引導點擊位置）

> 「我們今天測試的是網站好不好懂、順不順手，**不是考你本人**；網站有任何卡住的地方都是我們設計得不夠好。待會請邊看邊把你心裡在想什麼唸出來——包含哪裡看不太懂、或預期點下去應該看到什麼。」

## 2. 標準化測試任務（4 大任務：Happy Path ＋ `U2` / `U4` / `U5` 邊界路徑）

| 任務代號 | 對應風險路徑 | 情境指令（直接念給受測者） | 成功判準（Completion Criteria） |
|---|---|---|---|
| **T1** | Happy Path（首屏認知與活動頁轉化） | 「請先逛 5 秒首頁，告訴我『別的聚』『一起聚』『我的聚』分別是什麼。接著挑一個感興趣的近期活動點進去看完整說明，並完成報名或時間投票動作。」 | 1) 無猶豫區分三大聚集處語意。<br>2) 點進 `/e/[shortCode]` 看見完整 Markdown 資訊，觸達底部 RSVP／時間投票。 |
| **T2** | `U2`（零結果／空白頁恢復） | 「請在『別的聚』或『一起聚』一直篩選條件，直到畫面出現『目前沒有符合條件的內容』。請在不按瀏覽器上一頁的情況下，讓畫面恢復看得到活動或貼文。」 | 不依賴瀏覽器上一頁，直接點擊「清除全部篩選條件」或「查看全部領域」卡片按鈕恢復列表。 |
| **T3** | `U4`（海報文字偵測與分流防錯） | 「（切換幹部帳號後）打開社團管理後台『海報轉草稿 & 發文』，貼上一則包含日期、地點、報名費的社課招生活動文字，按下解析後選擇合適的地方發布。」 | 閱讀橘色分流提醒後，選擇「帶入建立活動表單」而非把活動招生活動海報誤發進日常動態流。 |
| **T4** | `U5`（驗證中斷與原路返回閉環） | 「在未完成校園信箱驗證狀態下，到『我的聚』或活動報名頁嘗試需要校園驗證的操作，跟著畫面引導完成信箱 OTP 驗證並回到原本頁面。」 | 經 `?returnTo=...` 進入 `/me`，完成驗證後看到「返回原本頁面 →」按鈕並順利返回。 |

## 3. 詞彙理解與 Smart Brevity 驗證問卷

任務結束後立刻詢問（**不可在任務前提示**）：
1. 請用自己的話解釋：頁面上的 **「時間待定，歡迎投票」** 與 **「只收新活動」** 是什麼意思？
2. 頁面上有沒有出現讓你看不懂的英文縮寫或奇怪名詞？（確認沒有殘留未翻譯內部術語）

## 5. 上線檢核與缺陷分級標準

- **Critical（阻斷級，發版前必修）**：任何主要任務失敗、無按鈕恢復空白畫面、驗證後找不到返回路徑、手機版水平破版或無法點到主按鈕。
- **Major（高摩擦，優先修改）**：受測者猶豫超過 10 秒、誤認名詞意義、或 SEQ ≤ 4。
- **Minor（微調）**：文案可更直白或間距微調，未阻礙任務完成。
- **過關建議目標**：關鍵任務成功率 ≥ 85%、平均 SEQ ≥ 5.5 / 7、SUS ≥ 75 分、詞彙困惑率 0%。

## 6. 計時資料與兩輪比較（2026-11-28 新增）

**受測者**：可以是招募的學生／幹部，也可以是開發者本人；都是真人實測，結果一律記錄並註明身分、裝置、日期。5 人結果只當方向性證據，不能單獨宣稱「快 10 倍」。

**順序**：
1. 第一輪（基準）：在首頁版面改版（審核報告 P0-3）**之前**測。已知的功能故障（P0-1）可以先修。
2. 對照組：同一任務也用 IG／DC／Canva 做一次；一半受測者先用 CluBar、一半先用舊工具，避免練習效應。
3. 第二輪：改版後用同一腳本、同一任務再測。

**網站自動計時**（`analytics_events` 的 `flow_start`／`flow_done`）：
- `student_rsvp`：進首頁或活動頁開始 → 報名成功結束。
- `officer_publish`：開始建立活動 → 第一個管道發出結束。
- 計時 ID 為任務級隨機值，只存在瀏覽器 30 分鐘，不連結帳號；90 天後自動清除 ID。

查詢各流程完成耗時（秒）：

```sql
SELECT split_part(source_surface, ':', 1) AS flow,
       count(*) AS done,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY flow_elapsed_ms) / 1000 AS median_s
FROM analytics_events
WHERE event_type = 'flow_done' AND created_at > now() - interval '7 days'
GROUP BY 1;
```

自動計時只涵蓋站內；IG／DC 對照組與跳出到外部 App 的時間，仍以主持人碼表為準。
