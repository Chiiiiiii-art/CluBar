## 2. Q1｜首頁應該展現什麼？

### 2.1 不同使用者確實期待不同的首頁

| 使用者 | 進首頁時真正想做的事 | 現在首頁給的 |
| :--- | :--- | :--- |
| 首次來的新生（S1/S2） | 「這裡有什麼？」→ 看幾張作品就懂 | 一段標語＋搜尋框＋測驗提示（內容在折線下） |
| 視覺滑手（S3） | 3 秒內看到好看的東西，否則滑走 | 第一屏沒有任何作品圖 |
| 碎片體驗派（S4） | 「這週有什麼可以去？」 | 藍色貼紙區＋1 張精選活動條（有幫助，但要再切分頁） |
| 已登入、已加入社團的學生 | 我追的社團最近有什麼活動 | 同上，沒有個人化 |
| 社團幹部 | 有沒有新提問、待審相簿、報名名單 | 同上，必須自己點進管理頁 |

### 2.2 現在的資訊量：工具太多、內容太少

實機量測（行動版 375×812，已登入）：

- 第一張內容卡頂端在 **768px**；扣掉底部導覽，**首屏 0 張內容卡**。
- 首屏可點元素 **29 個**，全部是入口與工具（測驗提示、搜尋、4 個貼紙捷徑、精選活動條、分頁、選校、導覽）。
- 重複入口：興趣測驗出現 3 處（頂部提示條、藍卡備援、桌機按鈕）；「零基礎／非社員／本週／免費」在藍色貼紙區與活動分頁篩選列重複出現。
- 已登入、已驗證的帳號仍顯示「第一次來？」提示條（判斷只看 localStorage 與選校 cookie，不看伺服器端的 onboarding 紀錄）。

這直接違反研究結論「首屏改為高圖佔比作品瀑布流，白話探索縮為輕量頂部膠囊」（user-research §二.4、PRD FR-DISC-02）。

### 2.3 建議（依人物誌優先序）

1. **行動版首屏至少露出 1.5 張內容卡**：主視覺標語縮成一行；搜尋縮成膠囊；藍色貼紙區與活動篩選列合併（只留在「近期活動」分頁）。
2. **測驗結果真的套用到首頁**：onboarding 結束帶上 `domain_id`；首頁讀取已存的 `domain_ids` 作為預設篩選，並在「已選條件」顯示，可一鍵移除。
3. **依身分加一條「細條」，不換整個首頁**（守住低認知負荷）：
   - 未登入／新訪客：無額外內容，直接看作品。
   - 已加入社團的學生：分頁上方一條「你追的社團本週有 N 場活動 →」。
   - 幹部：一條「熱舞社有 2 則新提問、3 張待審照片 →」（數字是待辦數量，不是人氣數字，不違反規則 3）。
4. 「第一次來？」提示改用伺服器端紀錄判斷，登入過的人不再出現。

附帶程式問題：`src/app/page.tsx` 會讀網址 `domain_id` 並用它查資料，但**沒有把它傳給 `DiscoverClient`**，所以畫面上不會顯示該領域被選取，「已選條件」也看不到。

## 3. Q2｜每項操作是否比 IG／DC 好 10 倍？

### 3.1 現況：沒有證據

- PRD v2 §6 明寫「取代主觀 `10x` 標籤」，改用 KPI，且**基準值要在試營運前兩週建立**——目前尚未建立。
- 研究裡的現況耗時（例：跨 4–5 平台找社團約 45 分鐘）是 AI 模擬推估值，不能直接當分母。
- 程式已有部分埋點（例：`event_promo_copy`、`discover_stream` 點擊來源），但**沒有「從開站到完成報名」的計時事件**，算不出 PRD 的「< 3 分鐘」。

所以現在對外只能說「設計目標是 10 倍」，不能說「已經達到 10 倍」。

### 3.2 各流程的 10 倍潛力評估

| 流程 | IG／DC 現況（研究推估） | CluBar 現況步驟 | 10 倍潛力 | 要先補的 |
| :--- | :--- | :--- | :--- | :--- |
| 新生找到適合的活動並報名 | 跨 4–5 平台、約 45 分鐘、常卡在 QR code | 首頁 → 近期活動 → 篩選 → 活動頁 → 登入 → 報名，約 5–6 步 | **高**（45→<3 分鐘 = 15 倍） | 首屏露出內容、測驗結果套用、計時埋點 |
| 幹部一次發到所有管道 | 每個平台各做一次圖文 | 建立活動 → 宣傳包複製 3 段 | **高** | 宣傳包移到「發布完成」畫面（現在藏在第 4 層） |
| 年度評鑑彙整 | 5 月前熬夜跨兩屆考古 | 平常勾「列入評鑑」→ 匯出／列印 | **高**（天 → 分鐘） | 真實社團試跑一次計時 |
| 重複私訊回答 FAQ | 開學週大量私訊 | 社團頁置頂 FAQ＋匿名提問 | 中（取決於學生是否先看 FAQ） | 量「私訊數」需幹部自報 |
| 換屆交接 | 帳密、2FA、雲端散落 | 3 步交接＋便條 | 高，但一年一次 | 實測步數與時間 |
| 社員日常發文 | 發 IG 限動 | 1 張圖＋1 句話 | **低**（IG 本身就很快，CluBar 優勢是曝光不是速度） | 不應以「速度 10 倍」宣稱，改以「社外觸及」衡量 |

### 3.3 建議

1. 每條流程定義「起點事件」與「完成事件」（例：`landing` → `rsvp_created`），補齊計時埋點。
2. 用現有腳本找 5 人做一次計時測試，同時讓他們用 IG／DC 做同一任務當對照組——這是最快拿到真實倍數的方法。
3. 提案中把「10 倍」限定在上表「高」的 3 條流程，其餘改用觸及率類指標。

## 4. Q3｜操作是否足夠直覺？

### 4.1 學生端：路徑短，但命名要學

- **品牌名詞當導覽**：「別的聚／一起聚／我的聚」需要先懂才會用；研究腳本 T1 第一題就是測這個，尚未測過。建議導覽加副標（例：「別的聚 · 探索」「一起聚 · 跨校」「我的聚 · 我的社團」），PRD §3.2 也是這樣寫的。
- **按鈕承諾與結果不一致**：「看票根 →」看起來會打開精選活動，實際只切換到近期活動分頁。建議直接連到該活動頁，或改文字為「看近期活動」。（「撕掉全部」是 [05-voice.md](design/05-voice.md) 明列可用的篩選回饋用語，且足夠直覺，保留不改。—2026-11-28 修訂）

### 4.2 幹部端：關鍵功能藏太深

找到宣傳包的路徑：底部「我的聚」→ 選社團 →「管理」→「活動」分頁 → 建立 → 「看活動頁」→ 捲到幹部區 →「LINE / IG 宣傳包」。**約 7 步，且沒有任何提示告訴幹部它存在。** 這是 PRD 定位為核心飛輪起點（FR-MY-03）的功能。

建議：發布成功後直接出現「發布完成」面板＝短網址複製鍵＋宣傳包三段文案＋限動圖下載。

### 4.3 角色快速定位（建議下一輪測試的任務）

| 角色 | 任務 | 預期點擊數（理想） |
| :--- | :--- | :--- |
| 新生 | 找一個本週零基礎活動並報名 | ≤ 4 |
| 幹部 | 發布活動並把宣傳文案貼到 LINE | ≤ 5 |
| 幹部 | 回答一則新提問 | ≤ 3（需首頁待辦條） |
| 社員 | 收到朋友傳來的活動連結並報名 | ≤ 3 |
| 承辦人 | 找出未換屆社團 | ≤ 3 |

## 5. Q4｜「任何人都能分享活動邀請卡，一點就看，登入後報名」

### 5.1 已經有的部分

| 需求 | 實作 | 位置 |
| :--- | :--- | :--- |
| 每場活動一個短網址 | `/e/[短碼]` | `src/app/e/[shortCode]/page.tsx` |
| 貼到 LINE／IG／DC 會出現預覽圖 | OG 圖 1200×630（`/api/og/events/[短碼]`），可設定隱藏地點 | 同上 `generateMetadata` |
| 訪客一點就能看完整活動 | 公開頁，不需登入 | `getPublicEventDetail(shortCode, null)` |
| 登入後報名 | 「使用 Google／微軟登入即可報名」→ 登入後 `callbackUrl` 回到活動頁 | `EventPageClient.tsx:801-806` |
| 幹部專用宣傳包 | LINE／Discord／IG 文案＋限動圖 | 活動頁幹部區「LINE / IG 宣傳包」 |

### 5.2 為什麼「找不到」

1. **一般使用者沒有分享按鈕**：實機在 `/e/ncu-dn-01` 搜尋「分享／複製／邀請」相關按鈕，只找到「複製行事曆訂閱連結」。
2. **活動卡（`EventCard`）沒有分享入口**。
3. **社團頁與貼文頁有 `ShareButton`，活動頁反而沒有**——現成元件沒接上。
4. **幹部發布後**只看到文字橫幅「專屬短網址：/e/xxx」，不能點、不能複製。
5. 次要：登入回來後要再按一次「留個位子」，報名意圖沒有保留；「限本校學生」的活動對他校朋友會擋在校園驗證——符合規格，但分享者需要事先知道。

### 5.3 最小修正（建議）

1. 在 `EventPageClient` 標題區接上現有 `ShareButton`，所有人可見；手機優先用系統分享選單（Web Share API），不支援時退回複製連結。
2. `EventCard` 加一個分享圖示（≥ 44px）。
3. 幹部發布成功橫幅加「複製連結」與「開啟宣傳包」兩個按鈕。
4. 登入回跳時帶 `?rsvp=1`，回到活動頁自動展開報名確認。
